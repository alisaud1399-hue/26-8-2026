الفئة 1: الوصول والتوازي
1. السماح بالاختيار اليدوي للموقع
inv_manual_picker مفتاح تشغيل واجهة الافتراضي: 0
يتحكم بظهور المنتقي (مبنى → طابق → غرفة) + حقل الكود اليدوي + فاصل "أو" في شاشة تسجيل الدخول للغرفة
الحالةما يظهر في شاشة تسجيل الغرفة
✓ مفعّل (1)زر مسح QR + فاصل "أو" + حقل الكود اليدوي + المنتقي الكامل (مبنى→طابق→غرفة موثقة)
✗ معطّل (0)زر مسح QR فقط — لا فاصل، لا حقل، لا منتقي
مستقل عن inv_qr_required_for_lock — حتى الأدمن يتأثر بدون استثناء
2. نمط التوازي بين الموظفين
inv_parallel_mode اختيار API + واجهة الافتراضي: off
يحدد إذا يمكن لعدة موظفين العمل على نفس الغرفة في نفس الوقت
النمطالسلوك عند محاولة فتح غرفة مفتوحة لموظف آخر
off — إيقاف⚠️ نافذة "الغرفة قيد الجرد من X" → [استلام / تراجع]
all — الكل✅ دخول مباشر مشترك + شريط "غرفة جرد مشتركة"
selected + الغرفة مدرجة✅ دخول مباشر مشترك + شريط الداخلين
selected + الغرفة غير مدرجة⚠️ نافذة "الغرفة قيد الجرد من X" → [استلام / تراجع]
3. الغرف المسموح بالتوازي فيها
inv_parallel_rooms JSON API الافتراضي: []
قائمة IDs الغرف المسموح بالتوازي فيها (يتطلب inv_parallel_mode=selected)
الإدخال: نص JSON مثل [189,276] — معرفة room_id من كود QR أو رابط فتح الغرفة
4. الباركود إلزامي لقفل الغرفة
inv_qr_required_for_lock مفتاح تشغيل واجهة الافتراضي: 1
يتحكم بضرورة مسح QR الغرفة مقابل السماح بالاختيار اليدوي
manualqr_requiredالنتيجة
مفعّلمعطّل✅ كل الطرق متاحة (مسح + يدوي + منتقي)
مفعّلمفعّل✗ باركيود فقط — المنتقي والكود اليدوي لا يظهران
معطّلأي✗ باركيود فقط (لا منتقي لأنه معطّل)
الفئة 2: دورة حياة الجرد
5. السماح باستلام غرفة قيد الجرد
inv_allow_takeover مفتاح تشغيل API الافتراضي: 1
هل يمكن للموظف الثاني استلام غرفة مشغولة — القفل الأول يتحول superseded (لا عودة)
الحالةالسلوك
✓ مفعّليُسمح بالاستلام — يُخرج الموظف الأول نهائياً من الغرفة
✗ معطّلرفض صارم: "الاستلام معطّل من إعدادات الجرد"
الاستلام = الموظف الأول يُ排出 نهائياً. لا يمكنه العودة لغرفته.
6. الإقرار الإلزامي قبل الإقفال النهائي
inv_require_oath_complete مفتاح تشغيل API الافتراضي: 1
يجب تأكيد "أُقفلت بعد إتمام الجرد فعلياً" قبل الإقفال النهائي — حماية إضافية
الحالةالسلوك
✓ مفعّليُرفض الإقفال النهائي بدون oath=1 (يظهر confirm dialog)
✗ معطّليُقبل الإقفال بدون تأكيد إضافي
7. مهلة عدم النشاط (بالدقائق)
inv_lock_timeout_min رقم صحيح (5–480) API الافتراضي: 30
مهلة تلقائية — عند عدم النشاط تُعلّق الغرفة
القيمةالسلوك
0بدون مهلة — القفل يبقى نشطاً حتى يُغلق يدوياً
5–480expires_at = NOW() + X دقيقة — عند انتهاء المهلة يتحول القفل
ملاحظة تنفيذية: لا يوجد كود حالي يحوّل القفل expired تلقائياً — يجب إضافة فحص expires_at عند كل طلب
8. الحد الأقصى لعمليات التعليق
inv_max_suspend_count رقم صحيح (0–99) API + واجهة الافتراضي: 3
عدد مرات التعليق المسموحة لكل موظف في نفس الغرفة — حماية مزدوجة (واجهة + سيرفر)
القيمةالسلوك
0غير محدود — عدد لا نهائي من التعليقات
N > 0بعد N مرات تعليق → رفض مع رسالة "يلزم مدير الأصول"
حماية مزدوجة: الواجهة تفحص RL.suspendCount + الـ API يفحص COUNT(*) FROM room_lock_events
الفئة 3: البيانات والجودة

allow_quickwarn_newالنتيجة عند مسح جهاز غير معروف
مفعّلمفعّلℹ️ تحذير: "جهاز جديد — يمكن تسجيله"
مفعّلمعطّلتسجيل تلقائي بدون تنبيه
معطّلمفعّل⚠️ تحذير: "جهاز غير مسجَّل — أبلغ المدير"
معطّلمعطّللا شيء

19. قسم إلزامي للغرفة قبل القفل
inv_dept_required_before_lock مفتاح تشغيل API الافتراضي: 1
يرفض قفل غرفة بدون قسم مرتبط (dept_id) أو حالة تحقق (parse_status=verified)
الحالةالسلوك
✓ مفعّل + غير موثقة✗ رفض: "الغرفة غير موثقة (بدون قسم مرتبط)"
✗ معطّليُسمح بالدخول
تسلسل فحوصات فتح الغرفة (API checkin)
1
فحص الجلسة
هل الجلسة نشطة؟ هل أنت عضو فيها؟
✗ جلسة غير نشطة → رفض✗ غير عضو → رفض (403)
2
فحص رادار المراقبة
هل أنت معلّق؟ هل الغرفة محظورة عليك؟
✗ معلّق من مدير الأصول → رفض✗ غرفة محظورة → رفض
3
فحص التوثيق
الغرفة موثقة (dept_id + parse_status + location_code)؟
✗ بدون قسم مرتبط → رفض (inv_dept_required)✗ بدون location_code → رفض (inv_block_undoc)
4
فحص الحالة الحالية
هل توجد قفل نشط لي؟ هل توجد غرفة أخرى مفتوحة عندي؟
✓ قفل نشط لي → استئناف مباشر✗ غرفة أخرى نشطة → رفض (inv_max_locks)
5
فحص التعارض
موظف آخر في الغرفة؟ ما نمط التوازي؟
✗ off + تعارض → نافذة استلام (inv_allow_takeover) ✓ all/selected → دخول مشترك
6
إنشاء القفل
INSERT + expires_at (حسب inv_lock_timeout_min) + rl_log
✓ دخول ناجح → شريط القفل + بدء الجرد
